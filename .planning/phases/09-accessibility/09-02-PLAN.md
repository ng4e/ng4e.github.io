1. **Focus indicators on nav links (per D-04, D-07):** The navbar sits on a dark/transparent background, so use white focus ring. Add to each nav link in the `.map()` loop, appending to the existing class string:
   `"focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-white focus-visible:ring-offset-2 focus-visible:ring-offset-primary rounded"`

   The key classes are: `focus-visible:ring-white` (white ring for dark bg contrast per D-07), `focus-visible:ring-offset-primary` (offset matches dark bg, avoids white gap per research Pitfall 3), and `rounded` (ring needs border-radius to look clean).

   Also add focus ring classes to both language links: `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-white focus-visible:ring-offset-2 focus-visible:ring-offset-primary rounded`

No additional mobile padding needed since MobileMenu handles mobile nav.

**In src/components/ui/Button.astro (per D-04, D-06, D-19):**

1. **Focus-visible ring (per D-04, D-06):** Add to `baseClasses` string:
   `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-accent focus-visible:ring-offset-2`

   The full baseClasses becomes:
   ```
   "inline-flex items-center justify-center gap-2 rounded-lg font-semibold transition-colors duration-200 focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-accent focus-visible:ring-offset-2"
   ```

   Using `ring-accent` (not `ring-white`) because Button is used on light backgrounds. The `rounded-lg` already exists, which gives the ring a matching border-radius.

2. **Small variant tap target (per D-19):** The small variant is `h-9` (36px), which is below the 44px WCAG minimum. Change the small size class to include a mobile minimum:
   ```
   small: "h-9 px-4 text-sm min-h-[44px] md:min-h-0",
   ```
   This enforces 44px minimum height on mobile/tablet, then removes the constraint on desktop (md+) so it reverts to h-9 (36px). The `h-9` sets the desktop intended height; `min-h-[44px]` overrides it on small screens.

   Actually, simpler approach: since `h-9` sets exact height and `min-h-[44px]` would override it on mobile, use:
   ```
   small: "px-4 text-sm h-11 md:h-9",
   ```
   This gives 44px (h-11) on mobile and 36px (h-9) on desktop. Cleaner than min-h override.

**In src/components/ui/Badge.astro (per D-03, A11Y-04 verification):**

1. **Contrast verification (per D-03):** With the accent color updated to `#336D93` (done in Plan 01), Badge's `text-accent` on white background achieves 5.60:1 contrast -- passes WCAG AA. The `accent` variant uses `text-accent` on `bg-accent/10` which is effectively a very light blue tint on white -- contrast is even higher. No code changes needed for contrast.

2. **Badge is not interactive** -- it is a `<span>` element, so no focus ring or tap target needed. Badges are display-only components. No changes required to Badge.astro.

Add a code comment at the top of Badge.astro to document the contrast verification:
